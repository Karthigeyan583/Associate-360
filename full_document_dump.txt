1.1 Non-negotiable rules
One BA record per person; extensions never create duplicate BA records.
Every agreement is a separate historical record; never overwrite prior agreement dates/rates.
Dates drive the system: joining, agreement end and compliance/document expiry create actions.
Dashboard first: users must immediately see what needs attention.
Calculated values are system-generated, not manually typed.
Sensitive data and documents are permission-controlled and auditable.
Excel import/export remains available.
Notification thresholds and recipients are configurable.
All critical actions are traceable to a user and timestamp.
1.2 Intentionally excluded from MVP
Full ATS/recruitment CRM
Payroll engine
Timesheet engine
Accounting/invoicing engine
Official VOG/BGC provider replacement
Complex project management

8.2 VOG control
Track the workflow; do not replace the official issuing/verification process.
Uploaded document must remain Received/Pending until an authorised verifier marks it Verified.
Store verifier and verification date.
Restrict access to the underlying document.
Do not store unnecessary screening detail.
8.3 BGC control
Track status and outcome with minimum necessary information.
Provider integration can be added later using provider reference/status.
Exceptions require reason and owner.

9.2 Anti-spam rules
Same threshold must not send twice unless manually resent.
Resolved conditions close outstanding alerts.
Changing agreement dates recalculates future thresholds.
Optional daily digest can group non-critical alerts.
Critical exceptions can bypass digest.
Email status: queued / sent / failed; provider delivery status when available.

15. Security, Privacy & GDPR
15.1 Security baseline
HTTPS/TLS everywhere.

OIDC/OAuth2-ready SSO.

Secure HttpOnly SameSite cookies.
CSRF protection and server-side validation.
ORM/parameterized queries.
XSS-safe rendering.

File upload type/size/content validation and malware scanning.
Secrets outside source control.
Separate dev/staging/prod.
Dependency vulnerability scanning.
Central error/security monitoring.
Encrypted backups with tested restore.
Tamper-evident audit logs.
15.2 GDPR
The Dutch Autoriteit Persoonsgegevens states that personal data must not be kept longer than necessary and that organisations should determine, document and justify retention periods. Exact retention periods must therefore be configured from the organisation's legal/privacy policy rather than invented in code. cite: turn0search0
Record source/purpose where required.
Maintain a retention matrix by data category.
Create review tasks before retention expiry.
Support data export, correction and deletion/anonymisation where legally appropriate.
Keep data longer only when another legal/business requirement justifies it.
Minimise BGC/VOG detail.
Restrict sensitive documents.
Audit access and administrative changes.

20. QA & Acceptance Criteria
Create BA with unique BA ID → searchable record.
Duplicate BA ID → blocked with existing record link.
Agreement end before start → blocked.
Active BA + agreement → readiness calculated.
Missing blocking compliance → NOT READY/ACTION REQUIRED.
Client rate change → Difference and Margin recalculate.
90-day expiry threshold → alert created once.
Same threshold checked next day → no duplicate.
Agreement date extended → old future alerts recalculated.
Second agreement created → first remains historical.
Exit recorded → BA becomes inactive and active alerts stop.
VOG upload → not automatically verified.
Unauthorized sensitive-document access → denied and logged.
Restricted export → sensitive fields excluded.
Excel import with invalid rows → valid rows previewed; invalid rows reported.
Retention action → audit event created.

All P0 workflows pass end-to-end testing.

Audit events exist for critical actions.

Import/export validation and security tests pass.
Backup restore tested.
Production secrets absent from source control.
Security review completed before launch.

Show agreement end date and days remaining together.

Remember user filter/sort preferences.
Show last updated timestamp where freshness matters.

Confirm destructive or high-risk actions.
Use inline validation.
